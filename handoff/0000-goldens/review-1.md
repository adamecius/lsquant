## Decision on G4 (graphene)

Regenerating `test/golden` on TCN reproduces chain1d byte for byte but not the two
graphene files: the `.chebmom2D` differs by at most 1e-15 in absolute value on elements
of order 1e-9 (relative 1.9e-6 only because the elements are tiny), identically at 1, 16
and 64 threads, and the committed `KuboBastin...JACKSON.dat` came from an older
reconstruction with a different grid and a NaN first row. Both committed files were
produced on another machine and toolchain.

The rule of AGENTS.md section 8 is that goldens are produced once, by the legacy build,
on the verification machine. Therefore:

- `goldens/stage0/graphene/` (the TCN files) **is** G4 for every stage from 1 on.
- `test/golden/` is not modified: it remains the legacy suite's own reference, which
  compares with tolerance 1e-6 (`graphene_regression`) and stays green.
- The two references differ by floating-point rounding only; the stage-3 gate uses
  `goldens/stage0`, byte for byte.

## Findings carried forward (no action in stage 0)

1. `test/golden/operators/graphene_golden.HAM.desc` carries bounds `[-3, 3]`, inside
   the graphene spectrum (Gershgorin radius about 7.5): with the sidecar present the
   moments diverge (`|mu|` about 1e73). The regeneration script deletes the sidecars
   before running, which is why G4 is sane. The descriptor is wrong and will be
   regenerated with Lanczos bounds when wannier2sparse `--bounds` is wired in stage 5;
   until then nothing reads it in the gates.
2. `FetchWannier2Sparse.cmake` prints a false "unavailable (offline?)" on a cold cache
   because it captures the nested cmake stdout into `W2S_BIN`. Legacy build file; fix
   in stage 7 when the legacy tree is retired.
3. Tutorial 04's README points to a non-existent `examples/04/operators`; the operators
   live in `test/models/chain1d_mag`. Tutorial 05's README references an undefined
   `dos.json`. README fixes, stage 7.
4. Tutorial 06 is qualitative only (rate-law exponent 1.26 vs 2, exact vs random-phase
   T1 differ by 20%, 75 minutes per run); it stays a smoke test (G8), never a gate.
5. The legacy time-evolution drivers flood stdout; `figures/out/stage_0/run.log` is
   left untracked.
