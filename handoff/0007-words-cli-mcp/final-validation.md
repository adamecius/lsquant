### 2. Tolerance mode (`GOLDEN_TOL=1`, tester's change to `scripts/check_goldens.sh`)

Every `compare()` that is not byte-identical is classified by a helper written into `$TMP`. The
result is TOLPASS (counted as passing) or DIFFERS (counted as failing), and the
`scripts/golden_diff.py` line is printed either way.

- **Moment files** (`*.chebmom*`): the two header lines must be identical as text, with the same
  layout, and `max_k |new_k - gold_k| <= 1e-12 * max_k |gold_k|` over the complex moments (the
  stage-6 measure).
- **Text curves** (`*.dat`):
  - the same layout;
  - the energy column identical as text;
  - every other value within one unit of the last printed significant digit. The unit is
    `10^(floor(log10|x|) - P + 1)`, where `P` is the largest number of significant digits
    printed in either file and the larger unit of the two values is taken. The test is
    absolute, never relative to the value.
  - Informative only: `max|d|/max|gold|`.
- **Every other file** (JSON, TSV, CSR): non-numeric text identical, and every number within
  the same unit rule.
- **`captured/index.tsv`**: an entry whose sha1 does not match passes if its capture passes
  against the golden capture.
- **Stage-6 thread rows** (`T=1 vs T=16`, same machine) stay `cmp`.
- **Totals** count byte-identical and TOLPASS separately.

A new part `7runs` (setup, the run files of `S7_SET`, comparison, totals) lets disjoint run-file
sets run as parallel processes. Three `7runs` processes plus one `7tail` make up `7`.

### 6. The legacy-final build on Aron (inside `7tail`, and the provenance check outside it)

**The failure inside the gate.** The harness builds `legacy-final` with
`cmake -DLSQUANT_BUILD_NEW_CORE=OFF -DLSQUANT_BUILD_INPUT_TOOLS=ON`, and on Aron this fails:
`Eigen/src/Core/util/Macros.h:749: #error Eigen requires at least c++14 support`. The causes:
- the legacy tree sets `CMAKE_CXX_STANDARD 11` and includes `<eigen3/Eigen/...>`;
- that include resolves through `-isystem ~/lsq-env/include` to Eigen 3.5.0, which needs C++14;
- the system Eigen (3.3.7) lacks `Eigen::Vector`, so it cannot replace it: tried with
  `-I` to a shim, which gives `'Vector' is not a member of 'Eigen'`.

So no C++11-compatible Eigen of 3.4 or later exists on Aron. This is an environment limit, not a
regression.

**Provenance outside the gate.** I built the legacy drivers with a compiler launcher that turns
`-std=c++11` into `-std=c++14` (`figures/out/final/scripts/cxx14_launcher.sh`, build log
`legacy_final_build_cxx14.log`: exit 0, 14 drivers). Then
`GOLDEN_TOL=1 scripts/check_goldens.sh 0 ~/fv2/legacy_build`:
- G1, G2 at 16, 1 and 64 threads: 6/6 byte-identical;
- G5 moments: 2 TOLPASS (6.7e-15, 6.9e-15);
- G5 curves: 4 DIFFERS, with exactly the numbers of section 3.

As noted there, these legacy G5 outputs are byte-identical to the new code's on Aron.

### 9. Smells

1. **The stage-5 table can crash without failing the gate.**
   - Without `W2S_TOOLS`, `figures/stage_5_table.py` raises `ModuleNotFoundError: hr_exactdiag`
     after 3 PASS rows.
   - `s7_goldens` counts the PASS/FAIL lines that were printed, and only fails when there are
     none. So a table cut short by a traceback counts as 3 PASS, 0 FAIL, and the gate does not
     notice (`gate7_runs_b_first_no_W2S_TOOLS.log`).
   - Proposal: require 16 rows or exit 0 from the table.
2. **The harness has two environment traps.**
   - It does not check `mktemp`: with a missing `TMPDIR` it ran on with `TMP=""` and tried to
     write `/s7/...` (smoke run 1).
   - Under a non-C numeric locale (`es_ES` on Aron), `printf %8.2f` fails on the run wall times
     (`invalid number`). The run uses `LC_ALL=C`.
